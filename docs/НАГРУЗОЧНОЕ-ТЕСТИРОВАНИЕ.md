# Нагрузочное тестирование «ЭкваЛайн»

## Где гонять нагрузку (важно)

| Среда | Можно? | Комментарий |
|-------|--------|-------------|
| **Локально** (`docker compose up`, `npm start`) | **Да, с этого начинать** | Безопасно, бесплатно, видно узкие места Node/PostgreSQL |
| **Отдельный staging на VPS** (копия боевого, другой домен/порт) | **Да, основной вариант перед релизом** | Реалистичнее CPU/RAM/сеть; не трогает клиентов |
| **Боевой сайт (production)** | **Нет** без явного окна и согласования | Риск простоя, rate limit, блокировка IP хостингом |

**Онлайн-сервисы** (вводите URL **staging**, не production):

| Сервис | Сайт | Бесплатно | Заметки |
|--------|------|-----------|---------|
| **Grafana k6 Cloud** | https://grafana.com/products/cloud/k6/ | Есть free tier | Загружаете сценарий `.js`, гоняете из облака по URL |
| **Loader.io** | https://loader.io/ | ~10k запросов/мес | Простые GET к публичным URL, без кода |
| **BlazeMeter** | https://www.blazemeter.com/ | Trial | JMeter/k6-совместимые сценарии |
| **Azure Load Testing** | https://azure.microsoft.com/products/load-testing | Trial | Если инфраструктура в Azure |

Для этого проекта удобнее всего: **k6 локально** → при необходимости **k6 Cloud** или **Loader.io** по staging-URL.

---

## Что нагружать в «ЭкваЛайн»

Публичные маршруты (без входа, без CSRF):

- `GET /api/public/settings`
- `GET /api/products`
- `GET /catalog.html`, `GET /index.html`

**Не гонять массово без подготовки:**

- `POST /api/auth/login` — лимит **40 запросов / 15 мин** с одного IP (`server.js`)
- `POST /api/feedback` — **6 / мин**
- `POST /api/orders`, PATCH оператора — нужна сессия + CSRF (отдельный сценарий)

Цель первого прогона: **каталог и публичное API** под 20–100 одновременных «пользователей».

## Вариант 1 — k6 на своём ПК (рекомендуется)

### Установка

Windows (PowerShell):

```powershell
winget install Grafana.k6
```

Или: https://k6.io/docs/get-started/installation/

### Поднять стенд

```powershell
cd C:\Users\verun\OneDrive\Desktop\dpp
docker compose up -d --build
```

Проверка: http://localhost:3001/catalog.html

### Запуск сценария из репозитория

```powershell
cd C:\Users\verun\OneDrive\Desktop\dpp
k6 run scripts/load/k6-public.js
```

Staging на VPS:

```powershell
$env:BASE_URL="https://staging.ваш-домен.ru"
k6 run scripts/load/k6-public.js
```

### Как читать результат

- `http_req_duration` p(95) — 95% запросов быстрее X мс (ориентир: **< 800–1500 мс** для API)
- `http_req_failed` — доля ошибок (ориентир: **< 1%**)
- Рост `429` — упёрлись в rate limit (для публичных GET обычно не должно быть)

## Вариант 2 — Loader.io (без установки)

1. Зарегистрироваться на https://loader.io/
2. Подтвердить домен (файл в корне сайта или DNS) — **только staging**
3. Создать тест:
   - URL: `https://staging.../api/public/settings`
   - Clients: 50
   - Duration: 1–3 мин
4. Повторить для `/api/products` и `/catalog.html`

Минус: нет сценария «логин → корзина → заказ».

---

## Вариант 3 — Grafana k6 Cloud

1. Аккаунт: https://grafana.com/auth/sign-up/
2. Cloud → k6 → Upload `scripts/load/k6-public.js`
3. Target URL = staging
4. Запуск из EU/US (нагрузка **не с вашего ПК**)

Полезно, если staging закрыт firewall и нужны внешние IP.

## Чеклист перед отчётом

- [ ] Указаны URL, дата, версия (`git rev-parse HEAD`)
- [ ] Профиль нагрузки: N виртуальных пользователей, длительность, ramp-up
- [ ] Метрики: RPS, p95 latency, % ошибок, CPU/RAM сервера (хотя бы `docker stats`)
- [ ] Вывод: выдерживает / не выдерживает целевую нагрузку (например 50 одновременных чтений каталога)

Шаблон вывода: *«При 50 VU p95 API 420 ms, ошибок 0.2%. Узкое место — PostgreSQL на GET /api/products при > 80 VU. Рекомендация: индекс / кэш настроек».»*

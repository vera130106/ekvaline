# 6 Документация к веб-приложению «ЭкваЛайн»

В данной главе описаны требования к среде запуска, руководство администратора по развертыванию серверной части и руководства пользователя по основным ролям: клиент, оператор службы доставки, менеджер контента сообщества, администратор, водитель-экспедитор.

---

## 6.1 Требования к аппаратным ресурсам

Клиентская часть приложения доступна через веб-браузер независимо от операционной системы рабочей станции пользователя. Для комфортной работы с интерфейсом рекомендуется:

- монитор с разрешением не ниже **1280×720** (для панелей оператора и администратора удобнее **1920×1080**);
- видеокарта с поддержкой современного браузера с аппаратным ускорением;
- клавиатура;
- манипулятор типа «мышь» или тачпад.

Для **развёртывания и эксплуатации серверной части** (узел, на котором выполняются `Node.js`, приложение `Express` и СУБД **PostgreSQL**) целесообразны следующие **минимальные** ориентиры:

- процессор **64-разрядный**, не ниже класса entry-level для серверов или современного ноутбука для разработки;
- **оперативная память:** не менее **2 Гбайт** для узла только с приложением; **рекомендуется 4 Гбайт и выше**, если на том же узле размещается PostgreSQL;
- **дисковое пространство:** не менее **2 Гбайт** свободного места под установку Node.js, зависимостей проекта (`node_modules`), исполняемых файлов и данных БД (с запасом на рост);
- сетевой доступ: для локального режима — **localhost**; для внешнего доступа — стабильное подключение и при необходимости **постоянный IP** или доменное имя у reverse proxy (например, Nginx).

Точные цифры нагрузки зависят от числа одновременных пользователей и объёма заказов; для учебного и демонстрационного стенда приведённых значений обычно достаточно.

## 6.2 Руководство администратора

### 6.2.1 Назначение программного средства

Веб-приложение **«ЭкваЛайн»** предназначено для представления сервиса доставки питьевой воды, оформления заказов клиентами, обработки заказов персоналом (оператор, водитель), ведения контента раздела сообщества (блог) менеджером и централизованного управления пользователями, товарами и настройками сайта администратором. Данные хранятся в **PostgreSQL**; бизнес-логика и API реализованы на **Node.js** (файл `server.js`).

### 6.2.2 Характеристики программного средства

| Компонент | Описание |
|-----------|----------|
| Платформа сервера | Node.js (LTS рекомендуется) |
| Веб-фреймворк | Express |
| СУБД | PostgreSQL |
| Управление пакетами | npm |
| Точка входа | `server.js` (скрипт `npm start` в `package.json`) |
| Порт по умолчанию | **3001** (переопределяется переменной окружения `PORT`) |
| Конфигурация | переменные окружения (файл `.env` в корне проекта; не публиковать учётные данные в репозиторий) |

Основные зависимости сервера (см. `package.json`): `express`, `pg`, `express-session`, `connect-pg-simple`, `bcrypt`, `cookie-parser`, `csrf`, `joi`, `dotenv` и др.

Для инициализации схемы и демонстрационных данных в проекте предусмотрены вспомогательные сценарии, например `npm run pg:setup` (см. `scripts/setup-postgres.js` и документацию в репозитории).

### 6.2.3 Обращение к программе (запуск)

**Локальный запуск**

1. Установить **Node.js** и **npm**, **PostgreSQL**, создать базу данных и пользователя (параметры подключения — в `.env` или переменных `DATABASE_URL` / `PGUSER`, `PGPASSWORD`, `PGHOST`, `PGPORT`, `PGDATABASE`).
2. В каталоге проекта выполнить установку зависимостей:  
   `npm install`
3. При первом развёртывании — подготовить БД (миграции/скрипты проекта, например `npm run pg:setup` — по инструкции проекта).
4. Запустить приложение:  
   `npm start`  
   (в среде **PowerShell** для смены каталога и запуска удобно использовать последовательность команд через `;`, а не `&&`, если версия оболочки не поддерживает оператор `&&`.)

Успешный запуск сопровождается сообщением в консоли с адресом вида **`http://localhost:3001`** (или другим портом, если задан `PORT`). Работа с функционалом выполняется в браузере по этому адресу.

**Рисунок 37** — Запуск ПС в локальном режиме: окно терминала с командой `npm start` и строкой вида «ЭкваЛайн: http://localhost:3001» (либо указанием порта из `PORT`).

**Развёртывание на выделенном сервере**

- на сервере размещается каталог с исходным кодом и статическими ресурсами;
- устанавливаются зависимости (`npm install`), настраивается `.env`, БД доступна по сети с узла приложения;
- процесс приложения запускается через `npm start` или менеджер процессов (systemd, PM2 и т.п.);
- для HTTPS и выдачи статики часто используется **reverse proxy** (Nginx и аналоги) с пробросом на порт Node.js;
- клиентам выдаётся **публичный URL** (домен или IP), по которому открывают сайт в браузере.

### 6.2.4 Входные и выходные данные

**Входные данные (примеры сущностей, с которыми работает система через формы и API):**

- данные пользователей: регистрация и вход (телефон в формате РФ, email, пароль, ФИО в профиле);
- каталог и заказы: товары, корзина, параметры заказа, адреса доставки, слоты, статусы;
- операторская обработка: назначение экспедитора, изменение статусов, причины отмен/правок;
- обратная связь и заявки с форм «Контакты»;
- контент сообщества: посты, опросы, факт дня и др. (менеджер);
- администрирование: создание пользователей с ролями, товары, настройки сайта (телефон, режим работы, тексты и т.д.);
- геокодирование адресов (через прокси-сервисы, если включены в конфигурации).

**Выходные данные:**

- HTML-страницы интерфейса и ответы JSON по маршрутам `/api/*`;
- сохранённые записи в БД (заказы, пользователи, аудит действий при необходимости);
- печатные формы и отчёты в операторской панели (в том числе вывод на печать при использовании соответствующих команд интерфейса);
- сообщения об ошибках валидации и состоянии операций (в интерфейсе и в журналах сервера).

### 6.2.5 Сообщения программисту

Специализированный протокол «сообщений программисту» в приложении отсутствует. При сбоях и отладке используются:

- текстовые сообщения консоли **Node.js** (неперехваченные исключения, ошибки подключения к PostgreSQL);
- ответы API с кодами HTTP и текстом ошибки (например, ошибки валидации Joi, отказ авторизации);
- стандартные сообщения СУБД при нарушении ограничений целостности (уникальность email и телефона, внешние ключи), если они не были перехвачены на уровне приложения.

В коде сервера (`server.js`), схем (`schemas.js`), работы с БД (`db.js`, `postgres.js`) и клиентских сценариях содержатся комментарии, облегчающие сопровождение и доработку. Рекомендуется использовать систему контроля версий (Git), не коммитить секреты из `.env` и вести журнал изменений при доработке API.

## 6.3 Руководство пользователя

Ниже приведены сводные инструкции по ролям. Номера рискунков **38–46** сохранены как ориентиры для подстановки **скриншотов вашего интерфейса ЭкваЛайн** (главная, форма входа, сообщения об ошибках, меню после входа, ключевые экраны панелей).

---

### 6.3.1 Клиент (покупатель)

#### 6.3.1.1 Назначение для данной роли

Клиент просматривает информацию о компании и продукции, пользуется калькулятором потребления воды на главной странице, оформляет заказы через каталог, ведёт **личный кабинет** (профиль, адреса, текущие и прошлые заказы), получает уведомления в шапке сайта после входа.

#### 6.3.1.2 Условия выполнения программы

- актуальный браузер с поддержкой JavaScript и cookies;
- доступ по URL приложения (локальный или выданный администратором);
- монитор, клавиатура и устройство указания **как в п. 6.1.**

#### 6.3.1.3 Выполнение веб-приложения

1. Открыть в браузере адрес сайта (например, `http://localhost:3001` на стенде разработчика).
2. На главной странице доступны разделы навигации: каталог, доставка, контакты, сообщество и т.д.  
   **Рисунок 38** — главная страница ЭкваЛайн.
3. Для регистрации нажать **«Регистрация»**, заполнить поля (имя, email, телефон, пароль по требованиям сервера). Для входа — **«Вход»**, указать телефон или email и пароль.
4. При неверных данных отображается сообщение об ошибке под формой.  
   **Рисунок 39** — пример сообщения об ошибке входа/валидации.
5. После успешного входа клиент может открыть **«Личный кабинет»** из шапки: уведомления, текущие заказы, история, профиль. Полноэкранный кабинет доступен также по странице `cabinet.html`. Выход — кнопка **«Выйти из аккаунта»** / **«Выйти»** в кабинете.
6. Оформление заказа выполняется из каталога: выбор товара, корзина, указание адреса и параметров доставки согласно формам страницы.

---

### 6.3.2 Оператор службы доставки

#### 6.3.2.1 Назначение для данной роли

Оператор обрабатывает поток заказов: фильтрует список, назначает экспедитора, меняет статусы, работает с картой и отчётами (в соответствии с возможностями страницы `operator.html`), выгружает данные при необходимости.

#### 6.3.2.2 Условия выполнения программы

Те же, что для клиента (браузер, URL). Рекомендуется широкий экран для таблицы заказов и карты.

#### 6.3.2.3 Выполнение веб-приложения

1. Войти под учётной записью с ролью **оператор** (учётные данные выдаёт администратор; на демонстрационном стенде после входа на главной выполняется перенаправление на `operator.html`).
2. В верхней панели доступны вкладки (заказы, карта, отчёты — по фактической вёрстке), кнопки обновления очереди и **выход** из учётной записи.
3. В таблице заказов выполнять действия по строкам: смена статуса, назначение экспедитора, массовые операции — в рамках прав, предусмотренных сервером.
4. **Рисунок 40** (для оператора) — основная страница панели с таблицей заказов и панелью фильтров.

---

### 6.3.3 Менеджер блога (контент сообщества)

#### 6.3.3.1 Назначение для данной роли

Менеджер создаёт и публикует материалы раздела сообщества: посты, факт дня, опросы, блоки и связанный контент (см. `manager.html`).

#### 6.3.3.2 Условия выполнения программы

Браузер, URL сайта; для загрузки изображений в постах — локальные файлы согласно формам.

#### 6.3.3.3 Выполнение веб-приложения

1. После входа под ролью **менеджер** выполняется переход на `manager.html`.
2. Использовать карточки действий («Новый пост», «Факт дня» и др.) для открытия форм, заполнения полей и отправки данных.
3. Кнопка **«Выйти»** в шапке панели менеджера завершает локальную сессию интерфейса и перенаправляет на главную (на стенде рекомендуется также явно выполнять выход через кабинет или администратора при смене политики безопасности).
4. **Рисунок 41** — панель менеджера с списком сценариев контента.

---

### 6.3.4 Администратор системы

#### 6.3.4.1 Назначение для данной роли

Администратор управляет пользователями (включая роли **клиент**, **менеджер**, **оператор**, **водитель**, **админ**), товарами и категориями, задаёт параметры сайта в форме настроек (`admin.html`).

#### 6.3.4.2 Условия выполнения программы

Браузер, URL приложения; для водителей при создании учётной записи важно заполнять **метку экспедитора**, согласованную с операторской таблицей заказов.

#### 6.3.4.3 Выполнение веб-приложения

1. Войти под учётной записью **администратор**; открывается `admin.html`.
2. В разделах панели: создавать пользователей, блокировать или менять роли, добавлять товары, править цены и остатки, сохранять настройки сайта.
3. Кнопка **«Выйти»** в шапке админ-панели выполняет выход с серверной сессией (запрос к API выхода) и переход на главную страницу.
4. **Рисунок 42** — админ-панель: блоки пользователей и товаров.

---

### 6.3.5 Водитель (экспедитор)

#### 6.3.5.1 Назначение для данной роли

Водитель просматривает список заказов, назначенных ему по данным оператора (сопоставление по метке экспедитора в профиле), обновляет статус доставки в пределах, разрешённых интерфейсом `driver.html`.

#### 6.3.5.2 Условия выполнения программы

Браузер на ПК или планшете; устойчивое сетевое соединение при работе в поле.

#### 6.3.5.3 Выполнение веб-приложения

1. Открыть страницу `driver.html`, войти по учётным данным, выданным администратором.
2. На экране **«Мои заказы»** отобразятся заказы с адресами, интервалами и суммами; использовать **«Обновить»** для актуализации списка.
3. **«Выйти»** — завершение сессии водителя.
4. **Рисунок 43** — таблица заказов в панели водителя.
